# Yaddaş Menecmenti (Virtual Memory)

Virtual yaddaş hər prosesə özünə məxsus adres məkanı təqdim edir. Fiziki RAM-dan müstəqil bu abstraksiya izoliyasiya və təhlükəsizlik təmin edir.

## Əsas anlayışlar

- Səhifələr (Pages): adətən 4KB, HugePages (2MB/1GB) performans üçün.
- Səhifələmə (Paging): virtual → fiziki xəritələmə; TLB ilə sürətləndirilir.
- Page Fault: səhifə RAM-da deyilkən yaranan hadisə; diskdən yüklənə bilər (demand paging).
- Copy-on-Write (COW): fork sonrası yaddaş səhifələri yazılana qədər paylaşılır.
- Heap/Stack: heap — dinamik allokasiya; stack — funksiya çağırışları üçün.
- NUMA: çox socket-li sistemlərdə lokal/non-lokal yaddaş gecikməsi fərqləri.

## Syscall-lar və API-lər

- brk/sbrk: tarixi heap genişləndirmə; müasir proqramlar adətən malloc → mmap istifadə edir.
- mmap/munmap: faylı/yaddaşı adres məkanına xəritələyir.
- mprotect: səhifə icazələrini dəyişir (RX/WX qaydası: kod regionları yazıla bilməz).

## Nümunə (mmap ilə faylı xəritələmə)

```c
#include <sys/mman.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>

int main(){
  int fd = open("data.txt", O_RDONLY);
  struct stat st; fstat(fd, &st);
  char* p = mmap(NULL, st.st_size, PROT_READ, MAP_PRIVATE, fd, 0);
  write(1, p, st.st_size); // stdout-a yaz
  munmap(p, st.st_size);
  close(fd);
}
```

## Praktik məsləhətlər

- Mümkün olduqda sıx oxunan böyük faylları mmap edin; copy və syscal-ları azaldır.
- Gecikmə kritikdirsə HugePages və ya jemalloc/tcmalloc kimi allocator-ları test edin.
- OOM Killer: yaddaş limitlərini (cgroups/ulimit) təyin edin; allocation uğursuzluğunu yoxlayın.
- Rust/C++-da allocator seçimlərini ölçün; fragmentasiya və latenceni nəzərə alın.

## Internals (Daxili mexanizm)

- Adres məkanı və VMA:
  - Hər prosesin `mm_struct`-unda VMA-lar (Virtual Memory Area) saxlanır: `[start, end)`, `prot`, `flags (anon/file-backed)`, `file+offset`.
  - `mmap()` yeni VMA yaradır/birləşdirir; `brk()` heap VMA-sını uzadır.
- Səhifə cədvəlləri və TLB:
  - x86-64: 4 səviyyə (PGD→PUD→PMD→PTE), hər biri 512 giriş; 4K/2M/1G səhifələr.
  - TLB tez-tez istifadə olunan xəritələri keşləyir; TLB miss → page walk (hardware) → PTE oxunuşu.
- Page fault axını:
  1) CPU PTE-ni tapa bilmir və ya icazə pozuntusu → fault (#PF)
  2) Kernel `handle_mm_fault()` çağırır
  3) Əgər lazımdırsa diskdən səhifə oxunur (readahead), ya da COW üçün yeni səhifə ayrılır
  4) PTE yenilənir, TLB flush lazımdırsa edilir
  5) İcra userspace-ə qayıdır
- NUMA:
  - Səhifə allokasiyasında node-yerli (`local`) seçmək latency-ni azaldır; `mbind`, `numactl`, cgroups cpuset.

```mermaid
flowchart TD
    A[CPU virtual adres] --> B{TLB hit?}
    B -- Bəli --> C[Birbaşa fiziki səhifə]
    B -- Xeyr --> D[Page walk: PGD→PUD→PMD→PTE]
    D --> E{PTE mövcuddur?}
    E -- Bəli --> F[TLB update] --> C
    E -- Xeyr --> G[Page Fault]
    G --> H[handle_mm_fault]
    H --> I{Anon vs File-backed?}
    I -- Anon/COW --> J[Yeni səhifə ayır + copy]
    I -- File-backed --> K[Diskdən oxu (readahead)]
    J --> L[PTE yaz + TLB flush]
    K --> L
    L --> C
```

### Observability və Praktika
- `perf mem`, `vmstat`, `sar -B` ilə fault/kswapd aktivliyini izləyin.
- `pmap`, `/proc/<pid>/smaps` ilə VMA-ları görün; `mincore()` isti səhifələri göstərir.
- `MADV_DONTFORK`, `MADV_HUGEPAGE`, `mprotect(PROT_NONE)` kimi məsləhətləri workload-a uyğun test edin.

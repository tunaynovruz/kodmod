# Fayl Sistemləri

Fayl sistemi faylları, direktoriləri və metadatanı təşkil edən qatdır. Proqramçı üçün əsas interfeys — fayl deskriptorları (fd), syscalls (open/read/write/fsync) və path resolution.

## Əsas anlayışlar

- Inode: fayl metadatası (ölçü, permission, pointer-lər). UNIX-lərdə directory sadəcə ad→inode xəritəsidir.
- Deskriptorlar: `stdin=0`, `stdout=1`, `stderr=2`; yeni `open()` → ən kiçik boş fd.
- Permission-lar: `uid/gid/mode`; `rwx` bitləri, `umask`, ACL-lər.
- Journaling: metadata (və bəzən data) üçün crash-davamlılıq; ext4, xfs, apfs.
- Caching: page cache buffer-ləri; ardıcıl oxu yazını sürətləndirir.

## Tipik syscalls

```c
int fd = open("log.txt", O_CREAT|O_APPEND|O_WRONLY, 0644);
write(fd, buf, len);
fsync(fd); // davamlılıq zəmanəti (latency yüksəkdir)
close(fd);
```

## Performans

- `O_DIRECT`/`O_SYNC`: latency/davamlılıq kompromisləri.
- Batch I/O: böyük buffer-lərlə oxu/yazı, syscal sayını azaldın.
- `rename()` atomikdir — tmp faylı yazıb atomik rename edin.
- Metadata bahadır: `stat()`/`readdir()` çağırışlarını optimallaşdırın.

## Fayl sistemi seçimi

- Linux: ext4 (default balans), xfs (böyük fayllar/paralellik), btrfs (snapshot/inline-checksum).
- macOS: APFS (snapshot, space sharing). Windows: NTFS (ACL, alternate streams).

## Təhlükəsizlik

- `chroot`/`pivot_root` sandbox üçün; `O_NOFOLLOW` ilə symlink hücumlarından qorunun.
- Temp faylları üçün `mkstemp()` istifadə edin; yarış şəraitini (race) önləyir.

## Internals (Daxili qatlar)

- VFS (Virtual File System) qatları:
  - `super_block` — FS instansının qlobal metadatası (mount zamanı yaradılır).
  - `inode` — obyekt metadatası (ölçü, blok pointerləri, izinlər).
  - `dentry` — path komponentləri üçün cache (ad→inode).
  - `file` — açıq fayl üçün per-deskriptor vəziyyəti (offset, flags).
- Path resolution:
  - `namei()` → `dentry` cache (DCACHE) → miss olduqda directory oxunuşu və `lookup` op.
- Page cache və writeback:
  - Oxu: page cache hit → birbaşa buffer; miss → `readpage/readahead` → disk.
  - Yazı: dirty pages → background writeback (`flush` daemons) → journal/meta update → disk.
- Journaling:
  - ext4: JBD2 jurnalında əvvəlcə intent/meta yazılır, sonra data/meta commit; crash zamanı replay.
- fsync()/fdatasync() yolu:
  - Dirty data/meta müvafiq sıra ilə sabit saxlanılır; latency yüksək ola bilər.

```mermaid
flowchart TD
    A[read("/var/log/app.log")] --> B[namei()/path walk]
    B --> C{Dentry cache hit?}
    C -- Bəli --> D{Page cache hit?}
    C -- Xeyr  --> E[Dir lookup + dentry yarad]
    E --> D
    D -- Bəli --> F[Buffer qaytar]
    D -- Xeyr  --> G[readpage/readahead]
    G --> H[Page cache-ə yaz]
    H --> F
```

### Observability və Praktika
- `cat /proc/sys/vm/dirty_*` writeback parametrləri; `iostat -x`, `pidstat -d` I/O təhlili.
- `strace` ilə `openat/statx/fstat/fdatasync` axınını izləyin.
- Məlumat davamlılığı üçün: `fsync` yalnız kritik fayllara; batch və `rename()` atomik pattern.

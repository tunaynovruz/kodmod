# Boot Prosesi və Init Sistemləri

Maşın açıldıqda firmware (UEFI/BIOS) cihazları hazırlayır, bootloader kernel-i yükləyir, kernel `pid=1` prosesini (init) başladır.

## Addımlar

- Firmware (UEFI/BIOS): hardware init, boot order.
- Bootloader (GRUB, systemd-boot): kernel və initramfs seçimi.
- Kernel: sürücülər, root filesystem mount, `pid=1` işə düşür.
- Init sistemi: xidmətlərin (services) paralel/ardıcıl start/stop-u.

## systemd əsasları

- Unit-lər: service, socket, timer, target.
- Journal: `journalctl -u my.service` loglara baxış.
- Şəbəkə: `systemd-networkd`, `NetworkManager`.

## Praktika

- Servisləri `Type=notify`/`Type=simple` ilə düzgün konfiqurasiya edin.
- Restart siyasətləri: `Restart=on-failure`, `RestartSec=`.
- Sağlamlıq yoxlaması (health): `ExecStartPre`, `ExecStartPost` skriptləri ilə.

## Internals (Boot axını və PID 1)

- UEFI/BIOS:
  - Firmware cihazları inicializasiya edir, UEFI Boot Manager vasitəsilə EFI tətbiqini (bootloader) işə salır.
  - UEFI Runtime Services bəzi saat/var dəyişənlərinə giriş verir.
- Bootloader (GRUB/systemd-boot):
  - Kernel imicinə (vmlinuz) və initramfs-ə göstəriş verir; kernel cmdline arqumentlərini ötürür.
- Kernel init mərhələləri:
  - `start_kernel()` → early init → driver-lər → `initramfs` mount → root filesystem kəşfi → `execve()` ilə PID 1 (init) başladılır.
- Initramfs:
  - Kiçik root şəkli; real root FS-ə keçid (pivot_root/switch_root) edən skriptlər/sistemlər saxlayır.
- PID 1 (systemd və ya alternativ):
  - Reaper rolu: zombi prosesləri təmizləyir, xidmətləri nəzarətdə saxlayır.

```mermaid
flowchart TD
    A[Power On] --> B[UEFI/BIOS]
    B --> C[Bootloader]
    C --> D[Kernel + cmdline]
    D --> E[Initramfs]
    E --> F[Root FS mount]
    F --> G[PID 1 (systemd)]
    G --> H[Units: service/socket/timer/target]
```

### systemd Internals
- Unit asılılıqları: `Requires/After/Wants`; target-lar boot mərhələlərini qruplaşdırır (multi-user, graphical).
- Socket activation: `.socket` unit əlaqə gələnə qədər servisin başlanmasını gecikdirir.
- cgroups inteqrasiyası: hər servis öz cgroup-da izolyasiya olunur; resurs limitləri tətbiq edilir.

### Observability və Praktika
- Boot debug: `systemd-analyze blame/critical-chain` boot gecikmələrini göstərir.
- `journalctl -b` bu boot sessiyasının jurnallarını çıxarır.
- Recovery üçün kernel cmdline: `systemd.unit=rescue.target` və ya `single`.

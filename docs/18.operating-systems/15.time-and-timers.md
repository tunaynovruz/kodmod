# Zaman və Timer-lər

Zamanla işləyən proqramlarda düzgün saat mənbəyinin seçimi və timerlərin dəqiq konfiqurasiyası kritikdir.

## Saat mənbələri

- Real-time clock: sistem saatı; NTP ilə dəyişə bilər → ölçü üçün uyğun deyil.
- Monotonic clock: geriyə getməyən, NTP-dən təsirlənməyən; interval ölçüləri üçün ideal.
- High-resolution clocks: nanoseconds dəqiqliyi; enerji/overhead balansına baxın.

```c
#include <time.h>
struct timespec t1, t2;
clock_gettime(CLOCK_MONOTONIC, &t1);
// iş
clock_gettime(CLOCK_MONOTONIC, &t2);
long ns = (t2.tv_sec - t1.tv_sec)*1000000000L + (t2.tv_nsec - t1.tv_nsec);
```

## Timer mexanizmləri

- `setitimer`/`timer_create` (POSIX): periodik və ya bir dəfəlik siqnal əsaslı timerlər.
- `timerfd` (Linux): file descriptor kimi timer — epoll ilə inteqrasiya olur.
- Windows: `CreateWaitableTimer`, `SetTimer`, `QueryPerformanceCounter` (QPC) ölçüm üçün.

```c
// Linux: timerfd ilə epoll
int tfd = timerfd_create(CLOCK_MONOTONIC, TFD_NONBLOCK);
struct itimerspec its = { .it_value = {1,0}, .it_interval = {1,0} }; // 1s periodik
timerfd_settime(tfd, 0, &its, NULL);
// tfd-ni epoll-a əlavə edin
```

## Vaxt sinxronu və drift

- NTP/Chrony: saat düzəlişi; real-time clock dəyişə bilər.
- Monotonic clock ölçüləri üçün təsirsizdir, lakin CPU freq dəyişməsi TSC əsaslı mənbələrə təsir edə bilər.

## Praktika

- Gecikmə-həssas event loop-larda `timerfd`/IOCP ilə timerləri eyni poll mexanizminə qoşun.
- UI və animasiya üçün wall clock, latency ölçümü üçün monotonic clock istifadə edin.
- Periodik işlərdə drift yığılmasının qarşısı üçün “schedule at fixed rate” əvəzinə “fixed delay” və ya absolute deadlines tətbiq edin.

## Internals (Clock sources, hrtimer, NTP)

- Clock sources və clockevent:
  - TSC (Time Stamp Counter): çox sürətli, lakin köhnə CPU-larda freq drift/unsync ola bilər; müasir invariant TSC sabitdir.
  - HPET/APIC timer: yüksək dəqiqlik, lakin oxunuş/xidmət gecikməsi daha yüksək ola bilər.
  - Kernel clocksource seçimini `cat /sys/devices/system/clocksource/clocksource0/current_clocksource` ilə görün; `available_clocksource` alternativləri göstərir.
  - clockevent cihazları timer interrupt-larını çatdırır; `NO_HZ`/tickless rejimi boş CPU-da periodic tick-i söndürə bilər.
- High-resolution timers (hrtimer):
  - HRTIMER müxtəlif dəqiqlik sinifləri ilə RB-tree-da saxlanır; yaxın trigger üçün CPU-local list.
  - Timer interrupt-da expired hrtimer-lər softirq kontekstində işlənir; `timerfd`, `posix timer` üst qatlardır.
- POSIX timer-lər və timerfd:
  - `timer_create(CLOCK_MONOTONIC, ...)` siqnal və ya `sigevent` ilə; `timerfd` isə fd kimi poll/epoll ilə inteqrasiya.
- NTP/Chrony sinxronu:
  - Kernel timekeeping PLL/FLL ilə clock drift düzəlişi edir (`adjtimex/ntp_adjtime`).
  - Real-time saat (wall clock) tənzimlənə bilər; monotonic saat təsirlənmir, lakin `CLOCK_MONOTONIC_RAW` daha “xammal” ölçü verir.
- Slew vs step:
  - Slew: vaxt kiçik sürətlə tədricən düzəldilir (monotoniclik qorunur).
  - Step: böyük fərqlərdə saat sıçrayır (real-time). Monotonic-ə təsir etmir.

```mermaid
flowchart LR
    A[User: timerfd_settime] --> B[hrtimer start]
    B --> C[RB-tree insert by expiry]
    C --> D[Clockevent interrupt]
    D --> E[hrtimer interrupt handler]
    E --> F[expire timers]
    F --> G[queue event to epoll]
    G --> H[userspace epoll_wait wakes]
```

### Dəqiqlik və Enerji
- High-res timer-lər (ns səviyyəsi) enerji sərfini artıra bilər; batch və timer coalescing istifadə edin.
- `CLOCK_MONOTONIC` əksər ölçmələr üçün balanslı seçimdir; `RAW` CPU freq dəyişmələrində belə sabit oxunuş verir (TSC əsaslı).

### Observability və Praktika
- `cat /proc/timer_list` aktiv timer-ləri göstərir; `perf sched timehist` vaxtlama gecikmələrini izləyir.
- Event loop (libuv, libevent, tokio) ilə `timerfd`/`kqueue EVFILT_TIMER`/IOCP timer-lərini eyni poll dövrünə qoşun.
- Periodik işlər üçün drift yığılmasını azaltmaq məqsədilə absolute deadline-lar (`TFD_TIMER_ABSTIME`) istifadə edin.

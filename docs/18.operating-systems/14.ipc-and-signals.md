# IPC və Siqnallar

Proseslər eyni maşında data mübadiləsi üçün IPC mexanizmlərindən istifadə edir. Siqnallar asinxron hadisələr üçün yüngül bildiriş mexanizmidir.

## IPC növləri

- Pipes/FIFOs: sadə byte axını; valideyn-uşaq proseslər arasında.
- UNIX Domain Sockets: eyni host daxilində socket API; fd-pass (SCM_RIGHTS) dəstəyi.
- Shared Memory: yüksək sürət, lakin sinxronizasiya tələb edir; `mmap`, `shm_open`.
- Message Queues: kernel əsaslı sıra; prioritetlər.

```c
// socketpair ilə iki tərəfli kanal
int sv[2];
socketpair(AF_UNIX, SOCK_STREAM, 0, sv);
write(sv[0], "hi", 2);
read(sv[1], buf, 2);
```

## Siqnallar

- Tipik siqnallar: `SIGINT`, `SIGTERM`, `SIGHUP`, `SIGCHLD`, `SIGSEGV`.
- `sigaction` ilə handler qeydiyyatı; async-signal-safe funksiyalara diqqət!

```c
#include <signal.h>
#include <unistd.h>
void h(int s){ write(1, "TERM\n", 5); }
int main(){ struct sigaction sa={.sa_handler=h}; sigaction(SIGTERM,&sa,NULL); pause(); }
```

## Praktika

- Graceful shutdown: `SIGTERM` → connection-ları bağla, state-i saxla, çıx.
- Watchdog-lar üçün `SIGHUP` ilə reload; `SIGCHLD` ilə child cleanup.
- Shared memory-də mutex/semafor ilə konsistensiyanı qoruyun.

## Internals (Signal delivery və IPC detalları)

- Signal delivery (Linux):
  - Hər thread-in `blocked` maskı və pending siyahısı var; proses səviyyəsində də `signal_struct` pending siyahısı mövcuddur.
  - `kill(pid, sig)` prosesə siqnal göndərir; `tgkill(tgid, tid, sig)` spesifik thread-i hədəfləyir.
  - Real-time siqnallar (SIGRTMIN..): sıralı və queuing-lidir; `sigqueue()` ilə payload (`sigval`) göndərmək olar.
  - Çatdırılma: hədəf thread seçilir → siqnal pending-ə əlavə olunur → blokda deyilsə oyadılır → userspace-ə qayıdışda `do_signal()` handler və ya default action icra olunur.
  - Handler detalları: `sigaction` ilə `SA_RESTART`, `SA_SIGINFO`; handler üçün user stack-da signal frame qurulur, `sigreturn` ilə geri dönüş.
- signalfd və eventfd:
  - `signalfd` siqnalları fayl deskriptoru kimi oxumağa imkan verir; epoll ilə inteqrasiya üçün rahatdır.
  - `eventfd` yüngül 64-bit sayğacdır; threadlərarası bildiriş və ya qonaq sürücülərlə kommunikasiyada istifadə olunur.
- UNIX Domain Sockets internals:
  - `SCM_RIGHTS` ilə fd-pass (file descriptor transfer); `SCM_CREDENTIALS` ilə göndərənin UID/GID məlumatı.
  - Datagram vs stream: datagram mesaj sərhədlərini qoruyur; stream bayt axınıdır.
- Shared Memory:
  - Sinxronizasiya tələb edir: futex/mutex/semafor; cache coherency və false sharing-ə diqqət.
  - `shm_open`/`mmap` və ya `memfd_create` ilə anonim paylaşımlı yaddaş.

```mermaid
flowchart TD
    A[kill(pid, SIGTERM)] --> B[Hədəf proses və/və ya thread tapılır]
    B --> C{Block mask siqnalı bloklayır?}
    C -- Bəli --> D[Process pending siyahısına əlavə et]
    C -- Xeyr --> E[Thread pending → oyat]
    E --> F[Kernel return yolu]
    F --> G[do_signal()]
    G --> H{Handler qurulub?}
    H -- Bəli --> I[User stack-da frame + handler]
    H -- Xeyr --> J[Default action (ignore/term/core/stop)]
```

### Observability
- `strace -e signal -f` siqnal axınını izləyir; `/proc/<pid>/status`-da `SigQ`, `SigBlk`, `SigIgn`, `SigCgt` sahələri.
- `perf trace` və `ftrace` ilə `signal_generate`, `signal_deliver` tracepoint-lərini aktiv edin.

### Praktika
- Asinxron-sinyal-safe qaydalar: handler içində yalnız safe funksiyalar; daha mürəkkəb iş üçün `signalfd` və ya self-pipe triki istifadə edin.
- IPC dizaynında backpressure mexanizmlərini (queue limitləri, timeouts) daxil edin; fd-pass istifadə edərkən sender/receiver lifetime-ı koordinasiya edin.
